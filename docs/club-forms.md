# 入会・継続・新歓フォームと春秋の名簿

幹部・管理者は `/Admin/club-forms` でフォームを作成し、`/Admin/grouping-roster` でその回答を名簿に反映します。旧形式の単一シートは、春秋の2参照先を確認・適用するまで引き続き利用できます。

## フォームの操作

作成済みフォームはカード右下の「フォームを削除」から、対象名と削除範囲を確認して削除できます。受付を終了し、Googleフォームと回答シートをGoogle Driveのゴミ箱へ移し、完了後に一覧から消えます。現在の名簿に使用中のフォームは、先に名簿の参照先を切り替えてください。共有の統合名簿・画像保存先は削除対象に含めません。通信に失敗した場合はカードが残り、再試行できます。Google Driveでファイルを復元しても管理一覧の削除記録は自動では戻らないため、管理を再開する場合は管理者が状態を確認します。

入会・春季継続・秋季継続・新歓撮影会・新歓食事会は、名前の質問の直下にふりがなの質問を置いています。新歓のふりがなは短文の必須欄で、カタカナ・名字と名前の間は全角スペース、例は「シャダン　シャレイドウ」です。参照フォームから今後のコピーにも引き継がれます。

新歓の企画名は、撮影会なら「【月/日（曜日）】シャレード新歓撮影会＠場所」、食事会なら「【月/日（曜日）】シャレード新歓食事会＠場所」を初期表示します。開催日時・場所を入力すると表示例が更新され、企画名が空欄ならそのタイトルを使います。手入力した場合はその名前を優先します。自動設定で保存した企画名は、日時・場所の再編集にも追従します。上段は企画名・場所、下段は開催日時・終了日時です。日時の入力ラベルでは「日本時間」を省略していますが、日時は引き続き日本時間として扱います。

1. Adminの「入会・継続・新歓フォーム」で、入会・継続・新歓撮影会・新歓食事会を選びます。
2. 西暦、春秋、会費または参加費、提出期限を入力します。新歓は企画名、開催日時、場所も入力します。金額0は無料です。画面の日時は日本時間です。
   新歓撮影会・食事会では「当日、参加費がかかる場合があります」ボタンで、参加費欄を金額の代わりにこの文言へ切り替えられます。「金額を指定する」で戻せます。作成済みフォームも一覧の「案内・料金・期限を変更」から切り替え、「変更を保存」でGoogleへ反映できます。
3. 「下書きフォームを生成」で、参照フォームの質問・選択肢・セクション・画像アップロードを引き継いだコピーと、新しい回答シートを作成します。元のフォーム・回答は変更しません。
4. 画像アップロードがあるフォームは「画像保存先の準備待ち」と表示されます。一覧の「編集」を開き、Googleが表示する「ファイルのアップロード先のフォルダが見つかりません」の「復元」を1回押します。Adminに戻り「画像保存先の準備を確認」を押すと、Google公式APIで実際の保存先を照合します。未準備・確認失敗の間は受付開始を止めます。春季・秋季の継続フォームにも会費振込確認用の添付欄があり、この手順が必要です。
5. 内容を確認し、「受付開始」で公開・回答受付を開始します。「今すぐ受付終了」、期限変更、未来の期限を指定して「受付を再開」も利用できます。西暦・春秋・種類を変える場合は新しく作成します。

Google公式APIは画像アップロード項目の作成・保存先変更を拒否するため、「復元」の1回だけはGoogle編集画面で行います。APIの受付フラグだけでは画像付きコピーの利用可否を判定できないため、保存先を別途検証します。生成する回答シートと統合名簿は日本時間・日本語設定です。

Driveに保存先フォルダを事前作成し、そのIDを既存の画像質問へ設定する方法も実検証しましたが、Forms APIの更新処理がHTTP 400で拒否されました。フォルダ作成後にもフォーム側の紐づけが必要なため、事前作成だけでは復元操作を省略できません。

春季継続の参照フォームには、2026-11-02に秋季と同じ会費振込確認用の添付欄を追加しました。任意回答・1ファイル・上限10MBで、手渡しの場合は会計に連絡する案内です。以降に生成する春季フォームにも引き継がれます。

参照フォーム5件の氏名例は「写団　写麗道」、フリガナ例は「シャダン　シャレイドウ」、学籍番号例は「1A234567」に統一しています。入会・春季継続・秋季継続の振込確認文は「会費の振込を確認できる画像をアップロードしてください。（会費を手渡しした方は回答不要ですが会計に直接連絡して下さい）」です。3フォームのテーマは指定の入会フォームに合わせ、青灰色（#607d8b）・背景（#d7dfe2）、Robotoの24/12/11に統一しています。

保存先は `contact@scharade.jp` の「幹部共有資料」です。同名の年度フォルダがある場合は再利用します。

- 入会・継続・回答シート・統合名簿：`（西暦）運営資料 / （西暦） 入会・継続フォーム`
- 新歓とその回答シート：`（西暦）運営資料 / （西暦） 新歓`

一覧には回答用フォーム・編集・回答シート・保存先のボタンを表示します。入会・継続には統合名簿も表示します。統合名簿の在籍者等の内容は、名簿の確認・適用後に保存されます。

提出期限は専用Apps Scriptの1分間隔のトリガーで受付終了します。通常は期限後約1分ですが、Google側の実行遅延・障害では遅れる場合があります。Webサイトが停止中でもトリガーは動きます。表示上の期限経過とGoogleの受付状態は別に確認でき、状態取得の失敗も画面に表示します。Googleの編集画面で手動変更した場合も次回取得で状態を確認します。

## 春秋の名簿を確認して適用

1. 「班分け用名簿」の対象年・春秋を選び、入会と継続のフォーム編集URL、または回答シートURL（`gid`付き）をそれぞれ入力します。作成済みのフォームを候補から選べます。
2. 「入会・継続の変更内容を確認」で、追加・復会・学年変更・退会・要確認事項・新しいアカウント連携候補を確認します。この時点では現在の名簿は変わりません。
3. 確認欄にチェックし、「名簿の参照先と退会処理を適用」で確定します。プレビューの期限は20分です。取得後に回答、アカウント、連携先が変わった場合は取得し直します。

同一人物の両フォームへの回答は継続フォームを優先し、同じフォーム内では最新の回答を使います。氏名は空白・全角半角を正規化します。学籍番号等の識別情報はハッシュにして照合に使い、同姓同名等で対応を確定できない場合は要確認とします。春の継続フォームにない性別は、その人の入会回答、既存名簿の順で補います。未対応の性別・学年を推測で分類しません。

両方に名前がない人、または継続フォームで「いいえ」「継続しない」と答えた人は退会対象です。曖昧な継続回答や同姓同名がある場合、既存の人物・連携・在籍情報を保護します。片方の取得失敗や見出し異常は空の名簿とは扱わず、適用を停止します。

学年が変わった人と復会した人は、確定済みのアカウント連携を使ってPortfolioの学年も更新します。退会者はOB/OGに更新します。名簿上の学年に変化がない人のPortfolioで編集した学年は保持します。新規連携では既存の初回学年設定の仕組みを使い、本人が保存済みの学年は保持します。写真・紹介文は変更しません。

確定した名簿はGoogleの統合シートの「在籍者」「退会者」「要確認」に保存します。この3タブは自動生成です。訂正は元の回答で行い、サイトで確認・適用してください。画像、振込証明、自由記述の回答は統合名簿へ転記しません。新歓フォームの回答者は名簿へ自動追加しません。

新規アカウント承認後の自動初期設定は、現在確定している期間だけを参照します。次期フォームを作成しても自動では切り替わりません。既存会員の退会・学年変更・復会の確認が必要なら、自動適用を止め、幹部が通常の確認・適用を済ませてから再試行します。承認時に全員選択されていた企画・通知・写真展への追加は、既存の初期設定処理を使います。

## 初回導入

専用のApps Scriptを **contact@scharade.jpで作成**します。会計・写真展のスクリプトや実行アカウントと共用しません。

1. 専用の標準Google Cloudプロジェクトを作り、Forms APIとDrive APIを有効にします。OAuth同意画面を組織内部・管理者メールで構成し、そのプロジェクト番号を専用Apps Scriptへ関連付けます。請求先の関連付けは不要です。`gas/club-forms/Code.gs` と `appsscript.json` を配置し、高度なGoogleサービスのDrive API v3も有効にします。
2. ランダムな32文字以上の共有秘密を生成し、Apps Scriptのスクリプトプロパティ `WEBHOOK_SECRET` とWebの `.env` の `CLUB_FORMS_WEBHOOK_SECRET` に同じ値を保存します。Git、チャット、ログへ秘密を出力しません。
3. `initializeClubForms` を一度実行します。GoogleのForms・Sheets・Driveと定期実行、画像保存先の確認用のForms APIと外部通信の認可が必要です。通信先はGoogle公式APIに固定しています。実行者と保存先の書込権限を検証し、`closeDueClubForms` の1分トリガーを1個作成します。
4. ウェブアプリを「自分として実行」「全員がアクセス」でデプロイし、`/exec` URLを `.env` の `CLUB_FORMS_GAS_URL` に保存します。公開エンドポイントは時刻・HMAC署名・一回限りのnonceを検証します。署名のない操作は受け付けません。秘密は実行権限を持つため厳重に管理します。
5. Webと `scharade-club-forms-worker` を反映・起動し、Adminの「Google連携を確認」でトリガーを含めて確認します。Portfolioの同期と承認後初期設定には既存の `scharade-accounting-worker` も必要です。
6. 本番で使う前に、試験用の下書きで質問・アップロード・新しい回答シート・保存フォルダ・受付開始・早期終了・期限終了・再開を確認します。元フォームの質問と回答を変更しないでください。参照テンプレートの変更で置換箇所が見つからない場合は、生成を停止します。

既存環境の `.env` に2変数がない場合、フォーム生成は無効になり、従来の名簿機能は維持されます。ローカルの自動テストはGoogleサービスの模擬環境を使い、実際のGoogleの認可・デプロイ・生成確認とは分けて記録してください。

## 再試行と復旧

- 作成・変更は `DATA_DIR/club-forms.json` の保存済み操作をワーカーが反映します。初回30秒から最大1時間間隔、8回失敗後は画面の「再試行」を使います。同じフォーム・操作を再利用します。
- Googleから応答が失われた場合、作成時に付けたファイル識別情報で照合し、二重に作成しません。確認不能なときは照合待ちにします。作成ボタンを押し直して別の操作を作らないでください。
- `RECONCILING` が継続する場合は、Googleの実行履歴・ゴミ箱・対象フォルダ・Driveの `clubFormsKey` を確認します。スクリプトプロパティの `CLUB_FORM_*` または `CLUB_TERM_*` にある作成待ちフラグを無条件で消してはいけません。Google側の実行完了と対象ファイルの有無を確認してから、バックアップを取り、保存されたIDまたは待機状態を修復します。
- 統合名簿の保存とPortfolioの更新は別の永続キューです。名簿画面から失敗を再試行できます。古い期間・リビジョンの保存が新しい確定内容を上書きしないように検証します。
- 再送中にプロセスを再起動しても保存済み操作から再開します。`DATA_DIR`、専用GASのスクリプトプロパティ、Google側のファイルはそれぞれ復元対象です。GASを別プロジェクトへ複製しても管理状態は引き継がれません。
- 連携秘密の漏洩時はGoogleとWebの両方を更新し、Web・該当ワーカーを再起動します。期限トリガーは引き続き元のプロジェクトで維持してください。

主な実装は `src/lib/clubForms.ts`、`termRoster.ts`、`rosterExports.ts`、`scripts/club-forms-worker.mjs`、`gas/club-forms/` です。Googleゲートウェイの認可・再送・期限処理は `tests/club-forms-gas.test.ts`、名簿反映は `tests/term-roster.test.ts`、画面は `tests/browser/club-forms.spec.ts` で確認します。

### 定員による受付終了

入会・新歓撮影会・新歓食事会は、作成時と「案内・料金・期限を変更」の中で「定員（人・任意）」を設定できます。1人以上の整数を入力し、空欄で人数制限を解除します。継続フォームには定員を設定しません。人数はフォームに保存された回答件数で数えます。

回答送信の通知で人数を確認し、定員以上なら提出期限前でも受付を終了します。Google側で1分ごとの確認も行い、通知の遅延・失敗を補完します。同時送信やGoogle側の通知遅延により、定員を超える回答が保存される場合があります。保存済みの回答を自動削除することはありません。フォームの説明には定員、管理カードには回答数と「定員到達で受付終了」を表示します。

受付中に定員を現在の回答数以下へ変更した場合も終了します。定員の引き上げや解除だけでは終了済みのフォームは再開しません。必要に応じて未来の期限を指定して受付を再開してください。定員に達したままのフォームは再開できません。

Googleの送信通知の実行設定には、ユーザー・プロジェクトごとに20件の上限があります。この専用連携は定期確認1件を使うため、定員付きで同時に受付できるフォームは通常19件までです。上限などで送信通知を設定できない場合は受付を開始せず、管理画面にエラーを表示します。受付終了・定員解除・削除で個別の通知設定を解放します。
