# サイトの会計管理

`/Admin/accounting` は承認済みの幹部・管理者がサイトのログインで利用する会計画面です。既存のAdminに会計セクションを追加し、会計スプレッドシートを引き続き原本として使います。操作前に確認画面を表示し、登録者の会員ID・表示名をGoogle側の操作履歴に残します。

## 共通名簿

会計は `member-activities.json` の **Adminで適用済みの roster** と確定済みの bindings を参照します。プレビュー・未適用の参照先・会計独自の名簿URLは使いません。単一名簿と、入会・継続回答を組み合わせた年度名簿の両方に対応します。

会計に送るのは安定した人物キー、氏名、大学、LINE名、在籍・要確認状態、確定したサイト会員IDです。学籍番号・性別・学年・本人識別ハッシュは送信しません。元の名簿には書き込みません。

名簿の適用・更新・本人連携で `accounting-roster.json` に最新状態を予約し、既存の会計ワーカーが再送します。ワーカーは元の適用状態も毎回比較するため、予約直前のプロセス停止からも復旧します。古い送信結果で新しい予約を消さず、接続失敗時は待機して再試行します。

旧会計人物のID・取引・未返金残高は保持します。既存の対応と確定した会員IDの連携を優先し、未対応の人物は氏名・LINE名・大学名から自動照合します。全角・半角・空白・英字の大小を正規化し、氏名とLINE名、氏名と大学名、一意な氏名の順で候補を評価します。名簿側と会計側の双方で一意に定まり、大学名やLINE名による矛盾がない場合だけ既存の会計人物に結び付けます。似た文字の推測や、異なる氏名をLINE名だけで同一人物とする照合は行いません。根拠と日時は会計人物の `rosterMatch` に保存します。

同名・重複候補・情報の矛盾、Admin側で本人または在籍が未確定の項目は、会計画面で確認します。在籍・本人対応が確認できない人への新しい立替の登録は止めます。過去の人物への返金は継続できます。照合方式の更新時には同じ適用済み名簿を再送でき、`matchingVersion` の更新後は同じ版の再送で対応をやり直しません。元の名簿の修正や更新は不要です。

「名簿」では対応待ちの人・対応先の候補・会計の人物一覧を、氏名・大学・LINE名の部分一致で検索できます。全角・半角・空白・英字の大小を吸収し、空白で区切った複数の検索語はすべて一致する候補に絞ります。対応先には未対応の会計人物だけを表示し、選択後と確定前に氏名・大学・LINE名を確認できます。検索条件を変えると選択を解除し、検索欄でEnterを押しても人物対応は確定しません。

## 接続と権限

- サーバー環境変数 `ACCOUNTING_ADMIN_GAS_URL`：同じ会計GASプロジェクトの専用Webアプリ。
- `ACCOUNTING_ADMIN_WEBHOOK_SECRET`：新規管理用署名鍵。会計GASと領収書受付GASの同名プロパティにも設定します。ブラウザーには渡しません。
- 従来の `ACCOUNTING_GAS_URL` / `ACCOUNTING_WEBHOOK_SECRET` は申請・アップロードの受付に維持します。受付用の鍵では管理操作・領収書閲覧はできません。

管理ゲートウェイはGoogleでは所有者として動作します。通信先自体はログイン不要ですが、v2署名・時刻・nonce・許可された操作を検証します。サイト側はすべてのページ/API/領収書で最新の会員権限を確認し、会員ID・役割の持ち込みを拒否します。既存の二段階認証とOrigin検査も適用します。

領収書はサイトの `/api/admin/accounting/receipts/:requestId` から返します。受付済み申請の添付であること、保存フォルダー・ファイル属性・サイズ・種類・内容ハッシュを検証します。Driveの公開共有は変更しません。受付GASの追加権限は `script.external_request` です。Driveから内容を取得するために使用し、Driveアクセスは既存の `drive.file` を維持します。

## 移行手順

1. 同じ会計GASに `Core.gs`・`Main.gs`・`SiteGateway.gs` と `Index.html` を保存。従来の非公開デプロイも新しい版に更新し、公開範囲を維持する。
2. Google側で新しい管理鍵を設定。`initializeWebsiteAccounting` を所有者が実行する。会計ブックに「会計操作履歴」「共通名簿記録」を追加し、旧独立名簿更新のトリガーを停止する。既存取引・設定・申請は書き換えない。
3. 同じプロジェクトに、所有者実行の専用Webアプリを新規配置。旧URLの公開範囲は広げない。
4. 受付GASに `AccountingReceipts.gs` を加え、管理鍵・追加権限を設定して既存デプロイを更新。
5. 検証済みサイトと接続設定を配置し、Web・会計ワーカーを再読み込み。共通名簿の反映状態を確認する。

## 通信切断・同時操作・復旧

各操作はUUIDと読み込み時のrevisionを使います。GASは同じプロジェクトのScriptLockで排他し、操作履歴を先に保存します。同じ番号の再送は内容を照合し、二重登録しません。別操作で内容が変わった場合は再読み込みを求めます。

保存途中の操作がある間は新規の書き込みと名簿同期を止めます。「中断した保存を再確認」で同じ処理を再開できます。取消途中の申請状態も復旧します。金額の処理は帳簿への記録のみで、送金や決済は実行しません。

巻き戻す場合は、配置時に退避したソースと配信成果物だけを戻します。導入後の取引・名簿・会員データ全体を古いコピーで上書きしないでください。旧独立名簿更新は再開せず、サイト連携を修復します。

## 検証

架空データで権限、共通名簿の反映・未適用状態の除外・過去人物の維持、署名・再送、部分返金、過払い拒否、保存途中の復旧、領収書の制限を検証します。本番の会計ブックには試験取引を追加しません。
