## サイト全体の仕組みと権限

公開URLは `https://scharade.jp`。ブラウザ → Nginx（HTTPS）→ PM2管理のNode.js／Astro → middlewareの認証・権限検査 → 画面・API、の順で処理します。AstroはリクエストごとにHTMLを生成します。現行Webサイトの実行にReact／Next.jsは使いません。

画面・APIはVPSの永続データと、microCMS・Adobe Lightroom・Gmail・Googleの各サービスを使います。会計・写真展・プッシュ通知の再送等は、Webとは別のPM2ワーカーが処理します。

| 利用者 | 主な入口・できること |
| --- | --- |
| 未ログイン | Home、About us、Activity、公開Gallery、Portfolio、Contact、各種公開案内 |
| 承認済み会員 | `/Member`。本人のPortfolio編集、企画参加回答、本人宛通知、写真展提出、立替申請、退会申請 |
| 運営（staff） | `/Member/manage`。企画・通知・班分け・写真展の管理 |
| 管理者（admin） | 運営機能に加え `/Admin`。サイト情報、アカウント・権限、名簿連携、削除申請の管理 |

承認状態と権限は別の項目です。Portfolioに表示する役職はログイン権限を与えません。運営・管理者には登録メールによる二段階認証があります。企画共有URLは未ログインでも公開部分を閲覧できますが、検索掲載は抑止します。通知本文・回答操作・管理機能には認可があります。

## 何を、どこで更新するか

| 更新したいもの | 操作・正本 | 反映のタイミング |
| --- | --- | --- |
| 共通情報、Home、About us、各種案内 | `/Admin` のサイト情報。未編集時は `src/data/siteDefaults.ts` | 下書き保存 → 実ページでプレビュー → 公開。保存だけでは公開しない |
| 活動記事・記事写真、トップのカルーセル | microCMSの `blog`・`card_image` | CMSで公開後。取得キャッシュは通常最大60秒 |
| Portfolioの紹介・写真 | 本人または管理者のPortfolio編集。正本はmicroCMS | 保存で公開内容を更新。取得キャッシュの影響はあり得る |
| Galleryの写真・アルバム | Lightroom。補助分類・公開範囲は `src/data/galleryAlbums.ts` も参照 | アルバム情報のキャッシュは30秒。公開／会員限定を未ログインでも確認 |
| 会員名・メール・権限・承認 | 管理画面のアカウント一覧／詳細 | 権限変更後は本人の再ログインが必要 |
| 企画・通知・班分け・写真展 | `/Member/manage` | 下書きと公開を区別。企画の公開・変更には通知が伴う |
| 立替申請・返金・会計 | 会員は `/Member/advance`、会計担当は非公開のGoogle担当者画面 | サイトの受付完了と担当者の承認・返金は別工程 |
| ページ構造、CSS、固定画像、公開ポリシー | ソースを修正し検証・ビルド・本番反映 | Gitコミットだけでは本番に反映されない |

デザイン変更は運営者の合意を得ます。保存が409になったら、別担当・別タブの更新を取り込んで再編集します。操作の詳細は[日常運用](editor-guide.md)にあります。

## 保存先と消してはいけないもの

| 保存先 | 内容・注意 |
| --- | --- |
| Git | ソース、固定画像・フォント・配信アセット、GAS、運用設定、資料、テスト |
| `.env` | サーバー専用キー・連携先設定。項目一覧は `.env.example`。値は安全な別経路で引き継ぐ |
| `DATA_DIR/users.json`・`sessions.json` | 会員・権限・セッション |
| `auth-security.json`・`signup-verifications.json`・`password-reset-tokens.json` | 二段階認証、新規登録メール確認、パスワード再設定。いずれもDATA_DIR内 |
| `DATA_DIR/site-content.json` | サイト情報の下書き・公開版・前の公開版 |
| `DATA_DIR/member-activities.json` | 企画・参加回答・通知・名簿対応・班分け・配信キュー |
| `DATA_DIR/exhibitions.json` と写真展ファイル | 設定、提出、配置、履歴、画像・出力、連携・再送状態 |
| `DATA_DIR/advance-requests.json` と `REC-*` | 立替受付、領収書・転送状態。転送途中の実物も独断で削除しない |
| `push-devices.json`・`adobe-auth.json`・`audit.jsonl` など | 通知端末、Adobe更新トークン、監査記録。いずれもDATA_DIR内 |
| microCMS／Lightroom／Google | 記事・原本写真・回答・会計・生成資料。GitやDATA_DIRだけでは復元できない |

既存の本番記録ではアプリは `/var/www/my-astro-app`、永続データは `/home/ubuntu/scharade-data` です。ローカルは通常 `DATA_DIR=./.data`。**ビルド生成物 `dist/` と永続データは別物です。** ビルド・再配置でDATA_DIRを初期化しません。JSONはアプリ経由で更新し、稼働中の直接編集を避けます。バックアップは列挙漏れを防ぐためDATA_DIR全体を対象にします。

## 開発・公開の基本

Node.js 22系（22.12以上、23未満）とYarn 1.22.22を使います。初回は `yarn install --frozen-lockfile`、`.env.example` を `.env` へコピーし、ローカル用の `DATA_DIR=./.data`・`SITE_URL=http://localhost:4321`・`TRUST_PROXY=0` を設定して必要なキーを安全に受け取ります。

| コマンド | 用途 |
| --- | --- |
| `yarn dev` | ローカル開発。通常 `http://localhost:4321` |
| `yarn run check` | Astro／TypeScriptの検査 |
| `yarn test` | Nodeの単体・結合テスト。`.ts` と `.mjs` |
| `yarn build` | 固定写真のWebP生成 → 型検査 → SSRビルド |
| `yarn test:browser` | Playwrightの隔離データを使ったブラウザ検証 |
| `yarn start` | ビルド済みサーバーを `.env` 付きで起動 |
| `yarn admin:create` / `yarn admin:password` | 専用管理者の作成／パスワード変更。VPS担当が対話端末で実行 |

公開は、現行コミットの記録 → データ・設定のバックアップ → 検証済みソース取得 → 依存導入 → テスト・ビルド → 登録済みプロセス再起動 → 実ページ確認、の順です。[公開手順](operations.md)に従います。過去に秘密情報除去のためGit履歴を差し替えた記録があり、古いcloneを安易にmergeしません。

### PM2のプロセス

`ecosystem.config.cjs` の定義は次の4つです。実際の登録・稼働はVPSで `pm2 status` を確認します。設定にあることだけでは本番起動済みとは判断できません。

| PM2名 | 実行元 | 役割 |
| --- | --- | --- |
| `astro-site` | `dist/server/entry.mjs` | Web画面・API |
| `scharade-accounting-worker` | `scripts/advance-worker.mjs` | 立替申請の会計GASへの再送 |
| `scharade-exhibition-worker` | `scripts/exhibition-worker.mjs` | 写真展のGoogle連携・転送・通知 |
| `scharade-push-worker` | `scripts/push-worker.mjs` | リマインダー・プッシュ配信キュー |

プッシュ配信は `PUSH_DELIVERY_ENABLED` とExpoの資格情報にも依存します。`.env.example` は配信無効を初期値にしています。本番有効化・実機受信は別の確認事項で、コード更新だけで確認済みと扱いません。

## SEO・公開範囲の保守

公開固定ページの正本は `src/data/publicPages.ts` です。新しい公開ページを作ったらここに案内を追加し、`/sitemap` と `/sitemap.xml` の両方を確認します。記事・公開Portfolio・公開Galleryは外部サービスから自動収集し、CMSは100件ごとの次ページも取得します。

XMLのURLは `https://scharade.jp` に統一します。記事・Portfolio・Galleryには実際の更新日時を `lastmod` として出力し、確認できる日時がない固定ページは省略します。外部API障害時はその系統を省略し、固定ページと取得できた他の系統を返します。URL数の急減時は連携障害も確認してください。

`/robots.txt` はクロール可否とサイトマップの場所を案内します。非公開情報の保護には認証・権限検査、検索掲載の抑止には `noindex` を使います。企画共有ページはXMLに載せず、`noindex` を読ませるためクロールを許可します。

本番反映後はHTTPSの `/sitemap.xml`・`/robots.txt` を確認し、Search Consoleの所有権を持つ担当者がサイトマップレポートから送信・読み込み結果・エラーを確認します。個別ページはURL検査で確認します。登録は検索掲載の保証ではありません。[Google公式手順](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)を参照してください。

## Gitの管理範囲

サイトに必要なソース・配信アセット・GAS・運用設定・資料・テストと `yarn.lock` を管理します。フォント・外部ライブラリのライセンスを保持します。`public/` は直接配信されるため、個人情報やバックアップを置きません。

`mobile/`（および誤記の `moblie/`）、`video-guide/`、旧 `next-app/` は管理対象外です。ローカルの実体は残しますが、新しくcloneした担当者には入りません。アプリ専用の `.easignore`・アセット生成スクリプト・ネイティブルーティングテストも除外します。Web側の通知・アプリ連携APIと参考資料は残します。アプリ本体や動画は別途保存先と管理方法を引き継いでください。

`.env` と退避版、`.data/`、秘密鍵・署名情報、依存、ビルド生成物、テスト出力、個人バックアップはコミットしません。共有する設定例は `.env.example` を使います。`.gitignore` は既に追跡中のファイルには効かないため、追跡解除とステージ内容の確認が必要です。漏洩時は削除だけでなくキー失効・変更と履歴対応を行います。

## 困ったとき

| 症状 | 最初の確認先 |
| --- | --- |
| サイトが開かない／502 | Nginx、`pm2 status`、`astro-site`ログ、ビルド結果 |
| 更新が消えた／表示が違う | DATA_DIRの指定、下書きと公開版 |
| ログイン・管理機能が使えない | 承認状態、role、メール二段階認証、会員データ、セッション |
| Gallery全体／一部写真が失敗 | Adobe認証・カタログ／署名URL期限なら再読み込み |
| 保存が409／保存できない | 同時編集、DATA_DIRの権限・容量・破損・残留ロック |
| 会計・写真展の転送が止まる | PM2ワーカー、GAS配置・権限・署名、Google実行状況 |
| メール・プッシュが届かない | メール設定／配信フラグ・端末設定、ワーカー、資格情報 |

復旧は[運用・復旧手順](operations.md)を使い、現在のデータを退避して実施します。整合性のあるバックアップにはWebだけでなく、同じDATA_DIRに書き込むワーカー・CLIも停止します。ロックは所有PIDの停止を確認し、そのロックだけを扱います。
