## 通知から提出まで

1. 運営以上の会員が写真展を作成する。
2. 対象者と日本時間の期間を設定する。`参加投票開始 < 参加投票終了 ≦ フォーム入力開始 < フォーム入力終了` が必要。
3. 通知本文を確認し「通知を送信して参加投票を公開」を実行する。通知を保存してから参加投票を公開する。
4. 対象会員がログインして参加・不参加・未定を投票する。参加投票期間と入力期間が会員のカレンダーに表示される。
5. 投票終了後、参加者だけが入力期間中に出展フォームを開始・保存・添付・提出できる。
6. 運営は提出内容、作品プレビュー、QRコードの実際の宛先、送信・Drive保存状況を確認する。

投票締切後の参加変更・対象者追加は運営以上が参加者一覧で行う。会員自身の投票は締切後に変更できない。既存の本人用URLを知っていても、ログイン中の会員と提出所有者が一致しない場合は入力・写真閲覧ができない。入力期間終了後は参加者が自分の保存内容を確認できる。


西暦は写真展の作成年（日本時間）を初期値とし、運営が変更できる。写真展名・年の変更は既存の写真展フォルダを移動・名称変更する。各ファイルの共有設定を自動で一般公開には変更しない。

既存Googleフォームと回答先は元の接続を保持する。新しいフォーム定義版を作成した場合のフォーム、以後保存する画像・出力資料は新アカウントに保存する。元画像のDrive送信対象は提出版が参照しているもの。下書きの写真はサーバーに保持する。Lightroomの既存の保存も継続する。

Driveへの画像・PDF送信は1MiBずつ分割し、途中までの保存量をGoogle側で照会して再開する。ファイルID・チェックサム・提出識別子で再送時の重複を防ぐ。回答は作品ごとにGoogleフォームへ同期し、画像URLとmmの配置情報を記録する。出力ボタンはダウンロードした資料をサーバーにも保存してDriveへの送信対象にする。読み取り用の既存GET出力APIは保存処理を行わない。

参照：[Driveの再開可能アップロード](https://developers.google.com/workspace/drive/api/guides/manage-uploads)。

## 既存データの移行

`scripts/exhibition-migrate.mjs` は既存フォームID・回答先ID・提出・画像を保持したまま、年、未公開の参加投票設定、元フォームの接続種別を補う。期間を勝手に設定しない。下書きを削除しない。

```sh
node --env-file=.env --experimental-strip-types scripts/exhibition-migrate.mjs
node --env-file=.env --experimental-strip-types scripts/exhibition-migrate.mjs --apply
```

初回は読み取りのみ。`--apply` の場合だけ排他ロックの下で保存する。同じ移行を繰り返しても既存の参加投票・年・フォーム接続を上書きしない。

未紐付けの下書きがある写真展は、運営が提出確認画面で出展者を指定するか保管対象にしてから通知を公開する。同じ会員の重複した下書きは選んだものを再開対象にし、残りは保管する。提出済みの作品を下書きへの紐付け操作で置き換えない。
