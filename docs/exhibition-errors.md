# 写真展フォームのエラー番号対応表

画面では「エラー番号：EXH-001」の次の行に、理由と対処方法を表示します。運営への問い合わせには番号と、操作していた写真展・作品を添えてください。番号は変更・再利用しません。

この対応表は出展者フォームの読み込み・開始・自動保存・提出・写真添付・タイトルボードプレビューと、共通の写真展応答処理が対象です。ログイン画面など他機能の番号は [サイト全体の対応表](./error-codes.md) を参照してください。公開ページ `/Errors` には両方の一覧を掲載しています。

| エラー番号 | 原因 | 表示する内容・対処方法 |
| --- | --- | --- |
| EXH-001 | 必要な写真が未添付 | 提出する写真の枚数分、写真を添付してください。展示・作品・未添付の写真番号も表示します。 |
| EXH-002 | 添付写真を確認できない | この作品の写真をもう一度選んで添付してください。別の人の画像は使用できません。 |
| EXH-003 | 作品・展示・提出先の情報を確認できない | 入力内容を控えて画面を開き直してください。解決しない場合は運営へ番号をお知らせください。 |
| EXH-004 | 文字数・行数・印刷枠を超過 | 警告のある項目の文字数や改行を減らしてください。項目別の上限や現在の行数も表示します。 |
| EXH-005 | 入力枚数と作品・写真の登録数が不一致 | 入力した作品数・写真枚数と、登録した作品・写真の数を合わせてください。 |
| EXH-006 | 必須項目や入力内容に問題がある | 必須項目と各欄の入力方法をご確認ください。項目名と修正内容を表示します。 |
| EXH-007 | 作品数・寸法などの上限超過 | 表示されている上限に合わせて修正してください。下書きは保存できます。 |
| EXH-008 | 写真の容量・種類・送信形式に問題がある | 写真は1枚20MB以下のJPEG・PNGを選んでください。 |
| EXH-009 | ログイン切れ・アカウントの変更 | 入力に使っていたアカウントで再度ログインしてください。 |
| EXH-010 | 参加条件・閲覧権限・編集リンクの問題 | 参加状況とアカウントを確認し、必要に応じて運営へお問い合わせください。 |
| EXH-011 | フォームの入力期間外 | 参加投票・入力期間のページをご確認ください。 |
| EXH-012 | 別の画面との保存の競合 | 「この端末の入力を保存」か「サーバーの下書きを使う」を選んでください。 |
| EXH-013 | 通信失敗・通信時間の超過 | インターネット接続を確認して、もう一度お試しください。自動保存は接続後に再送します。 |
| EXH-014 | フォームの読み込みに失敗 | 時間をおいて画面を開き直してください。 |
| EXH-015 | 保存処理に失敗 | 入力内容を控え、時間をおいてもう一度お試しください。 |
| EXH-016 | タイトルボードのプレビューに失敗 | 「プレビューを更新」を押してもう一度お試しください。 |
| EXH-017 | 端末への一時保存に失敗 | 保存が完了するまで画面を閉じないでください。 |
| EXH-018 | サイトから処理結果を確認できない | 入力内容を控えて画面を再読み込みしてください。 |
| EXH-019 | 写真展・提出内容が見つからない | 運営から案内されたページを開き直してください。 |
| EXH-020 | 処理の一時停止・未送信の入力が残っている | 保存状態や参加状況を確認してから、もう一度お試しください。 |
| EXH-021 | 送信する内容が多すぎる | 長い入力を短くして、もう一度お試しください。写真は1枚20MB以下にしてください。 |
| EXH-022 | 印刷用フォントの準備に失敗 | 印刷用の文字を確認する準備ができませんでした。文字が枠に収まるかは提出時に確認します。自動レポートには通信失敗・HTTPエラー・読み込み失敗・時間切れを区別して記録します。 |

## 修正計画と実装方針

1. 未添付の写真枠を作品の識別情報として検証する前に判定し、EXH-001で写真の添付を案内する。下書きの空欄・写真配置を保持し、ブックの画像は任意とする。
2. 文字計測用フォントの失敗結果を保存し続けないようにし、再取得を可能にする。待機は最大5秒とし、端末で文字を計測できなくてもサーバーで印刷枠を厳密に検証して提出を続ける。
3. エラーは番号と説明の2つを表示する。識別番号などの内部用語を避け、利用者が次に行う操作を示す。サーバーの文字警告は該当欄へ表示する。
4. 文字確認を始める前から二重送信を防止する。失敗した入力は残し、提出履歴は成功時だけ増やす。

APIの失敗応答は既存の `ok: false`、`message`、必要に応じた `issues` / `limitIssues` に安定した `code` を追加します。共通の `errorCode` にも同じ番号を付けます。APIの `message` は説明だけを持ち、画面で番号と組み合わせます。既存の保存データの移行は不要です。

フォント読み込みだけの失敗は提出エラーとして表示しません。「印刷枠に収まるかは提出時に確認します」と案内し、サーバーで通常どおり検証します。
