# 管理専用アカウント・代理ログイン・ロール別の表示確認

## 管理専用アカウントの表示

サイト管理専用アカウントは、通知先、会員の名前検索、アカウント一覧、名簿連携の候補、写真展の会員候補、写真の「いいね」した人の一覧に表示しません。通知の新規配信・予約配信からも除外します。管理専用アカウント自身は、管理・編集・通知作成を引き続き行えます。登録内容の確認は Admin の「管理専用アカウントの設定」から開きます。

判定は `users.json` の `siteManagement: true`、または既存の管理専用Portfolio ID `w_rozcjvv` です。名前・メールアドレス・管理者ロールだけで除外しないため、個人会員の管理者アカウントは会員として表示されます。`yarn admin:create` は新規の専用アカウントにこの印を付けます。個人会員の権限変更でこの印を付けないでください。

過去の回答・通知の送信者・監査記録は履歴として残します。元から公開対象外の管理専用Portfolioは引き続き公開一覧・サイト検索に出しません。

## 各アカウントへの代理ログイン

1. 管理者または幹部でログインし、Admin → アカウント一覧 → 登録内容を見るを開きます。
2. 「このアカウントでログイン」を押します。
3. 画面上部の「○○として代理ログイン中」を確認します。閲覧・編集・登録は対象アカウントの実際の権限で行い、保存するとそのアカウントの内容に反映されます。
4. 終了時は画面上部の「管理者へ戻る」または「幹部へ戻る」を押します。代理ログイン中に通常の Log out を押した場合も、代理ログインを終了して元のアカウントに戻ります。元のアカウントからログアウトするには、その後にもう一度 Log out を押します。

幹部は管理者・他の幹部を含む登録アカウントへ代理ログインできます。管理専用アカウントは通常の名前検索や会員一覧には出さず、Admin →「ログイン・ロールの表示確認」→「管理専用アカウント」から選べます。運営・一般会員は代理ログインを利用できません。

元のアカウントの二段階認証を含むログイン状態を利用します。対象者のパスワードを取得・表示・変更したり、本人のブラウザのログイン状態を置き換えたりはしません。未承認・パスワード再設定必須など、現在ログインできない対象者を選んだ場合は、その理由を示し、操作を許可しません。代理ログイン中に対象アカウントが削除・失効した場合も同様です。

パスワード・認証設定・プッシュ通知端末の登録・本人向け退会申請は代理ログイン中は利用できません。操作元のセキュリティ設定を誤って対象者へ結び付けないためです。必要な登録情報の変更は、代理ログインを終了し、既存の管理者用登録内容編集から行います。

切り替えは現在のログインセッションに属するため、同じブラウザの別タブにも反映されます。別のブラウザ・端末の操作元セッションや本人のセッションは変わりません。切り替え前に開いていたタブで保存しようとすると再読み込みを求めます。編集途中の場合は先に保存してください。

## ロール別の表示確認

元のアカウントの権限に応じて、次の入口・選択肢を表示します。

| 元の権限 | 入口 | 閲覧できるロール |
| --- | --- | --- |
| 管理者 | Admin → ログイン・ロールの表示確認 | 幹部・運営・一般会員・未ログイン |
| 幹部 | Admin → ログイン・ロールの表示確認 | 運営・一般会員・未ログイン |
| 運営 | Management → ロールの表示確認 | 一般会員・未ログイン |

画面上部に選択中のロールと「閲覧専用」を表示します。「表示の切り替え」から再選択し、「管理者へ戻る」「幹部へ戻る」「運営へ戻る」で終了します。運営の選択・復帰先は `/Management/view` で、Adminのアクセス権は付与しません。

権限は選択したロールで判定します。閲覧中は保存・登録・送信・削除をサーバー側で禁止します。個人情報を持たない一時的な表示用ユーザーを使うため、実在するアカウントの権限や登録内容は変わりません。個人宛ての通知、本人のPortfolio、参加状況などの表示を確認する場合は、上記の代理ログインを使ってください。会員情報を持たない一般会員プレビューでは、それらの一覧は空になります。

未ログイン表示中でも、元のアカウントのセッションの有効期限・二段階認証の条件は継続します。元の認証が期限切れ・失効した場合は改めてログインしてください。

## 実装・保存先

| ファイル | 役割 |
| --- | --- |
| `src/lib/accountVisibility.ts` | 管理専用アカウントと通常会員候補の共通判定 |
| `src/lib/adminViewPolicy.ts` | 元の権限に基づく代理ログイン・表示ロール・復帰先の共通判定 |
| `src/lib/adminViewState.ts` | 代理ログイン先・仮のロールの解決、古いタブの識別 |
| `src/lib/adminViewActions.ts` | 元のアカウント認証を再検証し、開始・切り替え・終了を保存 |
| `src/lib/auth.ts` | 元の認証と画面・APIで使う操作主体を分離 |
| `src/lib/requestIdentity.ts` | リクエストごとの代理操作情報・一時ユーザーを隔離 |
| `src/middleware.ts` | 閲覧専用制限、権限確認、古いタブからの更新拒否 |
| `src/pages/api/auth/admin-view.ts` | 同一サイトからのPOSTだけを受け付ける切り替えAPI |
| `src/pages/Admin/view.astro`、`src/pages/Management/view.astro`、`src/components/RoleViewPanel.astro` | 権限別のロール切り替え画面 |
| `src/components/AdminViewBanner.astro`、`src/scripts/adminView.ts` | 状態表示、終了ボタン、保存先の取り違え防止 |
| `tests/admin-view.test.ts`、`tests/browser/admin-view.spec.ts` | 認証・権限・保存・表示と候補除外の回帰テスト |

状態は既存の `DATA_DIR/sessions.json` の当該セッションの `adminView` に保存します。新しいパスワードや対象者のセッションは作りません。開始・終了は `DATA_DIR/audit.jsonl` に記録します。代理操作は元のアカウントを `actorId`、操作先を `actingAsUserId` として記録し、内容の保存APIへのアクセスも追跡できます。入力本文や認証情報はログに含めません。選択可能なロールは代理先ではなく元のアカウントで判定し、毎回再検証します。操作元が降格・失効した場合、古い表示モードでの書き込みは許可しません。

この機能や権限拡張より前の版へ戻す場合は、`adminView` を持つセッションを失効させてから戻してください。以前の版との権限・保存先照合の差を避けるため、単に状態の印を消してセッションを残す方法は使いません。今回のリリース用 `rollback.py --apply` は対象セッションと紐づく通知端末をロック下で失効させてから復旧します。他の会員のセッションは維持します。
