# 写真の詳細・いいね・通知と幹部権限

Portfolio、Blogの記事内写真、Galleryの写真は共通の詳細ポップアップを使用します。最初は情報欄を閉じて写真を画面いっぱいに表示し、写真をクリックすると情報欄が滑らかに開閉します。表示する作品情報・撮影情報がない場合は最大表示を維持します。スマホの横長写真は操作ボタン・情報欄もまとめて横向きにし、PCと同じ左右のレイアウトで表示します。写真を切り抜くことはありません。ホバー時は半透明のグレーと白文字で撮影情報を表示します。

## 写真情報の入力

参考画像の「憧憬」は作品タイトル、「Nikon Z5」はカメラ名、「Minolta 55mm f1.7」はレンズ名の例です。ホバー表示と詳細ポップアップには、それぞれの写真に保存した作品タイトル・カメラ名・レンズ名・F値・シャッタースピード・ISO感度を表示します。参考画像の文字を初期値として補完しません。

- Portfolio：本人の編集画面で、各写真の「写真情報を編集（任意）」を開きます。
- 写真展：既存の出展フォームでタイトル・キャプションを入力し、各画像の「この写真の撮影情報（任意）」でExifを編集します。組写真のタイトル・キャプションは作品共通、撮影情報は写真別です。
- Blog・通常Gallery：登録済みの写真情報を表示します。Adminの「写真のいいねランキング」は、いいねの概要とランキングを確認する閲覧専用画面です。

新規アップロードは画像の変換前にカメラ、レンズ、F値、シャッタースピード、ISO感度を取得します。既存画像は、残っているExifまたはLightroomのXMPから取得可能な項目を読み取ります。原本に情報が残っていない場合は手入力します。GPSや機器のシリアル番号は表示用データに取り込みません。入力済みの修正・空欄を優先し、削除した項目を自動取得で復活させません。

タイトル・キャプション・Exifは任意です。写真展フォームの作品タイトルも任意ですが、写真展名・提出者など既存の必要項目は引き続き必要です。未入力項目に「無題」や空ラベルは表示しません。通知ではタイトルがない写真を「写真」と呼びます。

## 匿名いいねと通知

ログイン中に新しく押されたいいねは会員単位で記録します。件数を閲覧できる本人・幹部・管理者は、ランキング、通知、写真の件数から会員名とPortfolioへのリンクを確認できます。通知では未読分、写真とランキングでは現在有効ないいねの会員を表示します。写真を表示できない通知も、通知の受信者は記録済みの会員名を確認できます。詳しくは [いいねした会員の表示](photo-likers-2026-11-02.md) を参照してください。

ログインせずに押せ、同じブラウザでは同じ写真に1件です。再クリックで取り消します。HttpOnly・SameSite Cookieで状態を保持します。Cookieの削除や別端末・別ブラウザでは別の訪問者になります。

microCMSは元画像URLから画像を識別し、表示サイズ・画質の違う配信URLでも同じ画像として扱います。Portfolioと同じ画像をBlogが参照すると、いいね数と状態を共有します。再アップロードによってURLが変わった写真は別画像です。撮影者はPortfolioの対応を一意に確認できる場合だけ自動表示します。

通知はPortfolioと写真展Galleryからのいいねを対象にします。写真展は最新の提出済み内容と添付画像から公開し、提出者に通知します。Blog・通常Galleryからは通知しません。写真展の運営限定・会員限定・一般公開は、一覧、写真本体、写真情報、いいねの各取得時に確認します。

ベルはMemberトップのPCでは「〇〇さんのメンバーページです。」と同じ行で、body-contentsの内側右端にあります。スマホではMemberと同じ行の右端にあります。各画面幅で表示するMember用のベルは1つだけです。未読時は共通の挨拶にも通知マークが付きます。写真ごとに未読いいねをまとめ、写真を開くと取得済みの通知だけを既読にします。対応するPortfolio写真がない場合はGalleryを開きます。

通知ポップアップ右上は「一括既読」「× 閉じる」の順です。一括既読は指定のリストとチェックのSVGを32pxで表示し、「すべて既読にする」の操作名を維持します。一括既読は表示中以外の写真の通知も対象とし、処理後に届いたいいねを未読として残します。既読操作は本人だけが行えます。

## ロール

一般会員 < 運営 < 幹部 < 管理者の順に権限を継承します。ログイン用の幹部は`users.json`の`role: "executive"`で管理し、Portfolioの掲載用役職・幹部表示とは別です。既存会員のロールは自動変更しません。

幹部は全運営機能に加え、アカウント管理の閲覧、一般会員・運営の登録内容編集と削除、一般会員・運営間の権限変更、班分け名簿の閲覧・同期・参照先変更・アカウント連携、全写真のいいね数閲覧ができます。幹部・管理者の登録内容や権限を変更・削除できるのは管理者だけです。サイト情報・他人のPortfolioの編集は管理者が行います。写真のランキング画面に編集機能はありません。

通常の会員・運営は自分の写真の件数だけ、幹部・管理者はすべての件数を閲覧できます。通知の閲覧・既読操作は全ロールで本人分だけです。昇降格時は既存セッションを無効にし、幹部は運営・管理者と同じ二段階認証の対象です。最後の承認済み管理者を降格・削除できない制限も維持します。

モバイルアプリのロール型・受信チェック・管理導線も更新しています。既存アプリは新ロールを受け取れないため、対応版を配布してから幹部を割り当ててください。

## 保存と検証

追加データは`DATA_DIR/photo-interactions.json`に保存します。写真情報、いいねと会員の識別情報、通知の既読位置を含むため、他のDATA_DIRファイルと一緒にバックアップしてください。ファイルロックと原子的保存を使用し、アカウント削除時には本人の写真情報・通知宛先・既読位置・いいねの会員情報を整理します。microCMSの画像配列のスキーマ変更は不要です。

検証はNode.js 22.23.4以上の22系で行います。写真・ロール・公開範囲・Exif・同時いいね・個別／一括既読の単体テストと、Chromium・Firefox・WebKitでのポップアップ、匿名操作、通知リンク、任意入力、権限、写真配置・ページ送り・会員画面の回帰テストを用意しています。Webサイトは2026-11-01に本番へ反映しました。アプリ配布、いいねのメール・プッシュ通知は今回の変更に含みません。

本番用Linux候補で関連テスト102件、型検査・ビルド、3ブラウザの69件が成功しています。[デザイン確認画像8点](design/photo-interactions-2026-11-01/README.md)を会話内へ出力してから同じ成果物を公開しました。本番反映の記録は[2026年11月の公開記録](deployment-2026-11.md)にあります。
