# Help・操作ガイドの実装計画と仕様

全ページのヘッダー下右上に丸いボタンと指定された情報マークSVGを置き、右からHelpパネルを開く。
やることがある場合はボタン右上に件数バッジを表示する。Helpを開く前から確認し、操作後も更新する。
パネルは検索、このページの使い方、各ツール・機能説明（全利用者・権限別）、やることリストの順。
登録済みの目的・言い換えから候補検索し、権限と対象データを確認して案内する。検索ボタンはメニューと同じSearchIconを共有し、押すと候補を表示・フォーカスする。候補の選択で案内を開始する。

## 案内の操作

- バナーに番号、説明、戻る、次へ、非表示を表示する。右上の閉じるボタンは案内を終了し、進行情報を破棄する。
- 非表示は進行位置を保持し、黄色の強調も消す。Helpの「案内を再表示」から続ける。
- 戻るは実際に表示した前の手順へ戻る。戻った手順は完了済みでも表示する。
- 次へは未操作でも説明だけ進められる。次へを押した時点で、完了済みの後続手順を飛ばす。
- 案内は送信・提出・承認を代行しない。該当ページ、見出し、入力欄、ボタンを案内する。
- 基本操作を順に案内し、詳細機能は必要に応じて選ぶ。詳細終了後は元の案内へ戻る。
- 同じタブ内で遷移・再読込後も継続する。無関係な遷移は一時停止し、終了・ログアウト時に破棄する。
- 見出しに黄色マーカー、操作箇所に黄色の浮いた矢印。内部スクロール・ダイアログにも対応する。
- バナーは画面下部を基本とし、対象を隠す場合は上部へ切り替える。対象の見える範囲とスクロール領域、画面端を照合し、矢印の向きを選ぶ。
- 対象の候補は記載順に評価する。見つからない場合や別のダイアログの背後にある場合は、無関係な見出し・画像に置き換えない。
- 案内の構成変更時は古い進行位置を破棄する（現在はカタログ版5）。同じ版の案内は再読込・画面遷移後も継続できる。

## 対象

公開・認証・会員・運営・管理画面の基本案内。詳細説明は組写真編集、レイアウト描画・整列・寸法・履歴、結果公開等。
やることは本人の未回答・未提出と、権限で処理できる共有管理業務。期限は日本時間。
管理業務は班分け再確認、登録承認、承認後の要手動対応、削除申請、会計の申請・返金・人物対応・中断保存。
会計は遅延読込とし、取得失敗で他の案内を止めない。外部画面・OSのファイル選択はサイト内の説明で補足する。

## サイト内登録承認

アカウント一覧で承認待ちを絞り込み、詳細の確認ダイアログから承認する。
幹部以上かつ対象を管理できることをサーバーで再確認する。既存のメール承認と処理・ロック・初期設定・通知を共用する。
二重操作、メール承認との競合、古い登録内容、初期設定やメール失敗を区別して扱う。承認取消しと否認の新規UIは対象外。

## 検証

検索・権限・期限境界・完了判定の単体テスト、承認の競合と再試行、案内の戻る・非表示・再表示・遷移・詳細復帰を検証する。
デスクトップとモバイル、Chromium・Firefox・WebKit、型検査とビルド、既存関連テストを確認する。

## 保守用の入口

- `src/lib/helpCatalog.ts`：ページ・目的・詳細説明と、その画面で強調する対象。権限と対象者の確認も行う。
- `src/lib/helpTasks.ts`：既存データから未対応項目を組み立てる。新しい作業状態を別途保存しない。
- `src/scripts/help.ts`：番号付き案内、戻る履歴、非表示・再表示、ページ遷移、矢印とスクロール。
- `GET /api/help/context?path=...&guide=...&entity=...`：認可された案内と、本人の完了状態。署名・認証情報を含むURL全体を送らない。
- `GET /api/help/tasks`：本人の回答・提出と管理業務。`source=accounting` は幹部以上に会計の項目だけ返す。
- `POST /api/admin/accounts/[id]/approval`：確認時の登録内容のrevisionを送り、既存の承認処理を共用する。停止済み・削除申請中のアカウントを再開しない。
- 操作に成功した画面は `help:statechange` を通知し、やることとバッジを更新する。表示中の画面では1分ごとにも確認する。

## 確認した不具合と修正

- 検索後の対象一覧の見出し指定を修正し、検索とやることの両方から案内を開始できるようにした。
- 閉じたダイアログ内に案内が残らないよう、表示先を現在のダイアログまたは本文へ移動する。
- SVGキャンバスも強調対象として扱い、編集画面内からHelpを開けるようにした。
- 完了状態の通信待ち中に終了しても、案内が復活しないようにした。
- 出展受付終了後にも現在のページの説明を残し、入力できない理由を案内する。
- 承認済みでも初期設定・開設メールの再試行が必要な場合は、その操作をスキップしない。
- ログアウト後は、非表示にした会員向け案内の進行情報を破棄する。
- 既存のモバイル検証は、導入済みの可変サイズのManagement見出しを固定96pxとしていた期待値を修正した。画面の見出し自体は変更していない。
