# 卒業生Portfolioの表示と保存

## 表示・編集ルール

- 学年が `OB/OG` のPortfolioは、Portfolio一覧の `OB/OG` 欄にだけ表示する。`All Members` と `Executives / 幹部` には含めない。`OG`、`OB`、`卒業` など既存の表記も共通の学年正規化を使う。
- 退会に伴う既存の名簿同期で学年が `OB/OG` に変わったPortfolioにも、この表示条件が適用される。
- 未ログインの一覧では、アイコンか投稿写真があるPortfolioを掲載する。
- 吉崎紗恵さんの `Sae Yoshizaki`（microCMS ID: `wpfqu4-8h10`）はアカウントを削除し、公開作品を保存している。サイト上の編集は承認済みの管理者ロールだけに許可する。後で別のアカウントに紐づいても、所有者という理由では編集を許可しない。
- この保存対象は、誤って学年が変更されても一覧では `OB/OG` に分類する。通常の卒業生Portfolioの所有者編集ルールは変更していない。

## 実装場所

- `src/data/portfolioVisibility.ts`: アカウント削除後も保管するPortfolio IDと、従来の一覧非掲載IDを管理する。
- `src/lib/auth.ts` の `canEditPortfolio`: 個人ページの編集リンク、編集画面、保存APIで共通の編集権限を判定する。
- `src/pages/Portfolio/index.astro`: 学年の正規化、卒業生の分類、All Members・幹部欄からの除外。
- `tests/alumni-portfolio.test.ts`: 所有者の再連携を含むロール別権限と学年表記の確認。
- `tests/browser/alumni-portfolio.spec.ts`: Chromium・Firefox・WebKitで、390/1440pxの一覧と編集画面・保存APIの権限を確認する。標準のブラウザ検証では専用の架空データを使用する。

## 今後同様の保管を行う場合

管理画面の通常のアカウント削除は、紐づくPortfolioも削除する仕様のまま。作品を残す依頼では通常の削除操作を使わず、対象IDを確認し、公開作品の復元・保存と編集権限の設定を先に完了する。microCMSで公開終了になっている作品は、管理画面で再公開する必要がある。

コードを切り戻しても、削除したアカウントや会員データを過去のバックアップ全体から戻さない。Portfolioの公開状態と学年はmicroCMS側のデータとして別に保持される。以前のコードへ戻すとAll Membersの除外条件と保存対象の編集制限が外れるため、切り戻す場合にも今回の権限・表示ルールを残すこと。
