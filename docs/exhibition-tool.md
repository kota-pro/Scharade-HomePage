# 写真展フォーム・タイトルボード運用

運営または管理者は `/Member/manage/exhibitions` から写真展を作成します。各写真展のボタンから「受付・通知・参加者」「フォーム作成」「展示室・壁面」「提出内容・QR」の画面を開きます。出展者は承認済みアカウントでログインし、参加投票が締め切られた後、参加者だけが入力期間中に `/Exhibition/<写真展ID>` を入力できます。自分の下書きは同じアカウントで再開します。

## 通知・参加投票・入力期間

管理画面で対象会員、参加投票の開始・終了、フォーム入力の開始・終了を設定し、設定を保存してから通知を送信します。期間は日本時間で入力し、`参加投票開始 < 参加投票終了 ≦ 入力開始 < 入力終了` の順序が必要です。通知を保存して参加投票を公開すると、対象者の通知一覧とカレンダーに表示されます。参加投票期間と入力期間は別々の予定になります。

通知先には全選択・全解除、学年の絞り込みと選択・解除、名前検索があります。全選択・全解除は検索で非表示になった会員も含みます。学年単位の操作は他の学年の選択を保持します。学年は会員名簿との紐付けを使い、未設定の会員も選択できます。

対象会員は `/Member/exhibitions/<写真展ID>` で参加・不参加・未定を回答します。締切後の参加変更は運営以上が参加者一覧で行います。入力期間外の保存・添付・提出はできません。入力終了後、参加者は自分の保存内容を確認できます。本人の編集リンクを知っていても、別アカウントから提出内容や添付写真を閲覧・編集できません。

改修前の未紐付け下書きは削除せず保持しています。運営が提出確認画面で出展者を指定するか、保管対象にしてから参加投票を公開します。実際の期間や出展者を自動で推測して公開しません。

## 出展フォーム

共通必須項目は名前、学年、作者名です。参加する展示ごとに単写真、組写真、ブックの数を指定します。単写真と組写真には作品タイトルと写真データが必要です。組写真では、作品数とは別に各組写真の写真枚数を指定し、写真ごとの幅・高さ・回転・X/Y位置を入力またはドラッグで調整します。グリッドスナップの間隔と有効・無効を切り替え、A3・A4・A5・JIS B4・B5・L・2L・任意サイズと縦横を選べます。写真間の横・縦の間隔は回転後の外接枠を基準にmmで表示・編集します。複数選択した写真を指定の間隔でグリッド・横一列・縦一列に並べることもできます。ブックはタイトルが必須で、作品画像は任意です。必要に応じて表紙や内容の画像をJPEG・PNGで添付できます。

画像はJPEGまたはPNG、各20MB以下です。原本はサーバーの `DATA_DIR` に保存され、プレビューを別ファイルに作ります。新しいDrive連携の設定後は、提出版が参照する原本を新アカウントへバックグラウンドで保存します。運営が写真展のLightroomアルバムを明示的に作成した場合だけ、提出済みの作品データをLightroomへも送信します。下書きや未使用の画像は送信対象になりません。画像一覧の公開機能は現在含まれていません。

企画展示は「企画展示セクションを追加」で作成します。通常展示と企画展示は同時に選択できます。追加質問は共通・展示セクション・作品のいずれにも置け、作品の質問は対象セクションと単写真／組写真／ブックを限定できます。共通質問にはセクションや作品種別の限定を付けられません。

展示セクションのタイトルと説明は全幅で編集します。「プレビューして保存」で確認画面を開き、「この内容で保存」で確定します。プレビューを閉じた場合と保存に失敗した場合は編集内容を保持します。

## Google Forms と回答スプレッドシート

Google Forms APIはフォームの作成・更新を扱いますが、回答の送信APIは提供していません。この実装では、Google Forms APIでフォームを作成し、Apps ScriptのForm Serviceで一作品につき一回答を作成します。連携済みスプレッドシートには、提出ID、版、展示セクション、レイアウトの数値、組写真のPNGレイアウト図、元画像のDriveリンク、Lightroomのアルバム・アセットIDが記録されます。

新しい保存先の所有者は `sharadeshashinten@gmail.com` です。新規フォーム・回答シート・提出済み原本・組写真PNG・出力資料を、マイドライブの `西暦＋年 > 公式サイト > 写真展タイトル`（例：`2026年 > 公式サイト > 秋季写真展`）に保存します。西暦は写真展の作成年（日本時間）が初期値で、運営が変更できます。旧年表記の写真展フォルダは、同じフォルダ・ファイルIDを保って新しい階層へ移動します。既存フォームと回答先は元の接続を保持します。

新アカウントのApps Scriptに `gas/exhibition/Code.gs` と `gas/exhibition/appsscript.json` を設定します。標準Cloudプロジェクトを紐付け、**Google Forms APIとGoogle Drive API** を有効にし、スクリプトプロパティに次を設定します。

| 名前 | 値 |
| --- | --- |
| `WEBHOOK_SECRET` | サーバーの `EXHIBITION_DRIVE_WEBHOOK_SECRET` と同じ32文字以上のランダム値 |

Webアプリは、新しい保存先のGoogleアカウントとして実行し、アクセス権を「全員（匿名アクセス可）」にしてデプロイします。サーバーからの通信はGoogleログインを利用しないため、この設定が必要です。全リクエストに5分以内のタイムスタンプとHMAC署名を要求し、秘密鍵を持たないアクセスは拒否します。Googleフォーム・回答シート・画像自体の共有権限は公開に変更しません。新しいデプロイURLは `EXHIBITION_DRIVE_GAS_URL` に設定します。URLは `https://script.google.com/macros/s/.../exec` 形式だけを受け付けます。従来の `EXHIBITION_GAS_URL` と `EXHIBITION_WEBHOOK_SECRET` は既存フォーム・シート取り込み用に保持します。

管理画面の「Googleフォームを作成」でフォームと回答スプレッドシートを作ります。既存の回答スプレッドシートを取り込む場合はIDを入力します。運営用アカウントに読み取り権限があることを確認してください。最初のシートを読み取り、1行1作品としてサイトのタイトルボード用データに取り込みます。1行目には名前（氏名）、学年、タイトル（作品タイトル）が必要です。作者名（作名）がなければ名前を使います。キャプション、撮影場所、使用機材、撮影設定、Portfolio URLにも対応します。元シートは変更しません。同じ作品の再取り込みは更新として扱い、無効な行は行番号と理由を返します。提出IDと作品IDがない元シートでは行番号を識別に使うため、取り込み後の行の並べ替えは避けてください。既存シートからの取り込みは写真データや展示配置の復元には対応しません。

## Lightroom

`.env` に `ADOBE_CLIENT_ID`、`ADOBE_CLIENT_SECRET`、`ADOBE_REFRESH_TOKEN`、`LIGHTROOM_CATALOG_ID` を設定します。管理画面の「Lightroomアルバムを作成」で写真展名のproject albumを作ります。写真展キューは専用の `scripts/exhibition-worker.mjs` が処理するため、本番では `ecosystem.config.cjs` の `scharade-exhibition-worker` を稼働させます。会計用ワーカーは従来の処理を継続します。ネットワークエラー時は未送信状態を保持して次回実行時に再試行します。

## 作成済みファイルの更新と写真展の削除

作成済みのGoogleフォームと回答シート、Lightroomアルバムは同じIDで更新します。フォーム設定の保存や写真展名の変更後はワーカーが設定を反映し、連携ボタンからの再反映でも新規作成しません。サイト内の提出版は保持し、変更前の質問への回答も回答シートの「提出データ」に記録します。旧仕様で複数作られたフォームは追加作成せず、最新のフォームを更新します。

運営以上は受付設定画面の「この写真展を削除」から、写真展名を入力して削除します。設定・回答・原本・プレビュー・出力資料を `DATA_DIR/exhibition-backups/` へコピーし、画像のチェックサムを照合してからサイト内の対象データを除去します。紐付くGoogleファイルはゴミ箱へ移動し、サイトが作成したLightroomアルバムは削除します。別の写真展、会計データ、無関係なDriveファイルやアルバムは処理しません。削除中の外部通信がある場合は終了を待ち、失敗した外部処理は自動再試行し、管理一覧に状況を表示します。

## タイトルボードと展示配置図

タイトルボードはA4縦を2列×4段、1枚あたり105×74.25mmで出力します。`public/fonts/zen-old-mincho/` のSIL Open Font License版Zen Old Mincho Regular/BoldをPDFに埋め込みます。タイトルは「」付き21pt Bold、作者名14pt Regular、学年10pt Regular（作者名との間隔6.5mm）、キャプション10pt、任意の撮影場所・使用機材・撮影設定は8ptです。任意項目が空なら表示されません。

PDFを出す前に、タイトル・作者名と学年・キャプション・任意情報が指定枠に収まるか確認します。文字を縮小せず、収まらない作品と理由を返します。運営は提出内容を直してから再出力します。新しい提出のPortfolio QRは、提出に紐付く承認済み会員のPortfolioを自動で付与します。既存シート取り込みでは名前が一意に一致する承認済みアカウントを使用し、同姓同名や外部HTTPS URLは運営が確定します。提出確認画面では実際のQR画像と宛先を確認できます。

展示室は左側のキャンバスで大まかな形を描き、アンカーポイントをドラッグして編集します。右側で頂点座標、壁の長さ・角度・高さ、扉・窓、壁面作品、展示台、ブックをmm単位で決定します。取り消し・やり直しができます。壁に作品や扉・窓がある場合、関連付けが失われる頂点追加・削除はできません。出力は全室PDF、各室PNG/SVGです。平面図と壁面正面図に実寸・開口部・作品を描き、範囲外や重なりは出力図の「要確認」に表示します。ダウンロードした資料はサーバーにも保存し、新しいDrive連携の送信対象になります。

## 設定コマンドと人間が行う操作

サーバーでNode 22を使い、アプリのディレクトリから次を実行します。`prepare` は秘密鍵を表示せず `.env` に生成します。`connect` は署名認証とForms APIの疎通が成功してからURLを保存します。

```sh
node --experimental-strip-types scripts/exhibition-google.mjs prepare-drive
node --experimental-strip-types scripts/exhibition-google.mjs connect-drive https://script.google.com/macros/s/DEPLOYMENT_ID/exec
node --experimental-strip-types scripts/exhibition-google.mjs check-drive
```

外部・テストモードでは、今回利用するForms・Drive権限の認証許可が7日で失効します。継続運用にはGoogle Auth Platformのブランディングを構成し、公開ステータスを外部・本番へ変更してください。説明ページは `/exhibition-integration.html`、データの取り扱いは `/exhibition-privacy.html`、利用案内は `/exhibition-terms.html`、承認済みドメインは `scharade.jp` です。Googleでの公開設定を変更する際は本人の承認を受けます。

本人が行う必要がある操作は、Googleログインのパスワード・二段階認証・本人確認、およびGoogleのOAuth権限画面での内容確認と許可です。Cloud初回利用、ブラウザ操作機能のサイトアクセス、秘密鍵保存、実行アカウントとWebアプリ公開範囲も、必要な時点で承認を受けます。パスワード・認証コードはチャットに送らないでください。API有効化、コード配置、Cloudプロジェクト紐付け、共有秘密鍵の設定、Webアプリのデプロイ、サーバー設定、疎通確認は承認された範囲で自動実行します。

新しいGoogle接続の完了条件は、署名付きhealth応答（gatewayVersion 3、Forms API・Drive API利用可能、所有者が新しいアカウント）、実際のフォーム・回答シート作成と作品回答の反映、指定したDrive階層と所有者、元画像・PNG・出力資料の保存、再送時の回答・ファイル数不変です。URLや秘密鍵の保存だけでは接続完了としません。

従来の `contact@scharade.jp` との連携は2026-10-08、新しい `sharadeshashinten@gmail.com` との連携は2026-10-09に完了条件を確認済みです。新アカウントの認証設定は外部・本番です。[レビュー記録](./exhibition-review-2026-10.md) と [改修記録](./exhibition-redesign-2026-10.md) を参照してください。

## 展示室の保存・再利用と図形・注記

写真展の「展示室と壁面レイアウト」で「展示室の保存名」を入力し、「名前を付けて新規保存」で会場を保存します。他の写真展では「再利用する展示室」から選び、「選んだ展示室を追加」→「展示室レイアウトを保存」で使えます。部屋の形、壁高、扉・窓、展示台、図形・注記を共有するライブラリです。作品の割り当ては写真展ごとに設定します。「選んだ保存済み展示室を更新」は同じ保存先を上書きします。保存・読み込みの権限は運営以上です。

キャンバスの「＋」「−」と倍率で25〜800%の拡大・縮小、「全体表示」で倍率と移動位置を戻せます。「画面を移動」はキャンバス内だけを移動します。頂点・記号・作品をドラッグしている間はページのスクロールを抑止します。選択・移動と画面移動は手のひら、ドラッグ中は握った手、描画はペン、頂点追加は＋、削除は×のカーソルです。

「部屋を描く」で頂点をクリックし、交差しない3点以上の形を作った後、描画中の頂点を選ぶと閉じられます。「描画を完了」ボタンでも閉じられます。2点だけでは面積がないため閉じられません。取り消しで前の形へ戻せます。

右側の「図形・注記」では電源、ドア記号、四角形、楕円、文字・数字を追加できます。ドラッグで位置を決め、右側でX/Y、幅・高さ、回転、文字サイズ（すべて実寸mm、回転のみ度）と表示文字を編集します。壁に紐付く扉・窓は従来の「扉・窓」で設定し、扉は開閉の弧を平面図に表示します。「配置した作品の展示者名を表示」で作者名と作品タイトルを表示できます。注記・図形・展示者名はPDF・PNG・SVGの出力にも反映します。
